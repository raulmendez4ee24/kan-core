# Onboarding Execution

Purpose: turn intake data into a durable onboarding case with the next operational step clearly queued.

When to activate:
- new onboarding intake
- setup or kickoff workflows
- integration readiness checks

Preferred strategies:
- reuse existing case by case_key
- enrich with website/docs context when available
- queue the next real onboarding step, not just a summary

Common mistakes:
- losing intake context across sessions
- creating duplicate onboarding cases

Completion checklist:
- onboarding case updated
- missing integrations identified
- next action queued
